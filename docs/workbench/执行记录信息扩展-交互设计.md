## 1. 核心设计决策

**头部两行不动，新增信息全部进展开区。** 头部信息密度已最优（标题+状态 / 时间·资源·耗时），新增的复核人、流程单、步骤时间属于低频或明细信息，放展开区按需呈现。

**资源明细从列表改为表格**，操作下沉到行级：查看详情全状态可用，重试/AI 诊断仅失败行可用。

数据模型现状：编排记录已具备 `submitter/reviewer/job.startTime` 展示模式（机制已预留），操作记录侧空白——本需求是将编排侧已验证的模式对齐到操作记录，并将明细升级为表格形态。

## 2. 数据模型变更

```ts
/** 关联流程单（变更单/事件单，均可选） */
export interface ExecutionTicket {
  type: 'change' | 'incident'   // 变更单 / 事件单
  no: string                     // 单号，如 CHG-2026-0088
  title: string                  // 标题
  summary: string                // 摘要（2-3 句）
  submitter?: string             // 提单人
  createTime?: string            // 创建时间
}

// ExecutionRecord 新增字段：
interface ExecutionRecord {
  ...existing
  reviewer?: string              // 复核人（可空）
  tickets?: ExecutionTicket[]    // 关联流程单（0-N 个）
}

// ExecutionDetail 新增字段：
interface ExecutionDetail {
  ...existing（startTime/endTime/duration 已有，mock 补值）
  returnInfo?: string            // 返回信息（原始文本，展示时智能识别类型）
}
// 约定：startTime/endTime 在 mock 中直接存预格式化字符串（'HH:mm:ss' 或 'MM-DD HH:mm:ss'），
// 表格与弹窗直接渲染，不做运行时格式转换（与编排 job.startTime 惯例一致）
```

## 4. 资源明细表格（Q4/Q5 落地）

### 4.1 列定义

> 宽度约束：抽屉 900px，展开区可用宽约 860px，六列合计须 ≤ 860px，报错列取剩余弹性空间。

| 列 | 字段 | 宽度 | 说明 |
|---|---|---|---|
| 资源 | `pkDisplay`（+`pkValue` 次级小字） | 200px | 主名 + IP/标识，超长省略 + tooltip |
| 状态 | `execStatus` | 80px | 状态 tag（成功/失败/执行中/等待） |
| 开始时间 | `startTime` | 110px | 预格式化字符串（`HH:mm:ss`，跨天显示 `MM-DD HH:mm`）；无则 `-` |
| 耗时 | `duration` | 70px | `X.Xs`；无则 `-` |
| 报错 | `errorMsg` | 自适应（约 240px） | 仅失败行显示，danger 色，超长省略 + tooltip |
| 操作 | — | 160px | 按状态条件渲染（4.2），失败行三按钮紧凑排布 |

### 4.2 操作列（行级操作矩阵）

| 资源状态 | 操作按钮（文字链 `type="primary" link`） |
|---|---|
| 成功 / 执行中 / 等待 | `查看详细信息` |
| **失败** | `查看详细信息` · `重试` · `AI 诊断` |

- 单资源重试：toast 确认（与现有 `handleRetryFromHistory` 占位级别一致，demo 不打开执行弹窗——单资源重试无参数可改，直接确认即可）
- 单资源 AI 诊断：**新增 `openDiagnosticForDetail(record, detail)`**，打开 DiagnosticPanel，`failedResources` 仅传该资源（`pkValue`/`pkDisplay`/`errorMsg`）——现有 `openDiagnostic(record)` 接收整条记录并内部过滤全部失败资源，行级入口须独立（Q5）

### 4.3 表格行为

- `size="small"`、行高紧凑；抽屉 900px，展开区可用宽约 860px，列宽已按此约束设计（§4.1），不产生横向滚动
- 展开区表格无分页（单条记录资源数 ≤ 10）
- 原"点击整行查看详情"行为移除（改由操作列按钮承担，职责明确）
- 与抽屉顶部「批量重试失败 / 导出」按钮（抽屉级、跨记录）不冲突，各自保留

## 5. 流程单 Popover 规格（Q3）

- 触发：点击单号文字链（主色 + hover 下划线）
- 内容：单号+类型（标题行）→ 描述/标题 → 摘要（2-3 句）→ 提单人 · 创建时间（次级色小字）
- 宽度 300px，`trigger="click"`，点击外部关闭；无摘要时只显示标题+元信息

## 6. 资源详情弹窗（Q6）

**形态**：`el-dialog`（宽 640px），标题 `资源详情 · {pkDisplay}`。

**内容分区**：

| 区块 | 内容 | 说明 |
|---|---|---|
| 基本信息 | 起止时间（startTime → endTime）+ 耗时 + 状态 | 两列描述列表 |
| 执行参数 | `paramsInfo` | key-value 表格；空则隐藏区块 |
| 资源信息 | `resourceInfo` | key-value 表格；空则隐藏区块 |
| 报错信息 | `errorMsg` | 仅失败：danger 底色块全文展示；无则隐藏 |
| **返回信息** | `returnInfo` | **类型徽标 + 对应只读代码块**（见 §7）；空则隐藏 |

## 7. 返回信息智能识别（Q6 核心机制）

### 7.1 识别策略（优先级顺序）

```
detectReturnType(content):
1. trim 为空 → text（不展示区块）
2. 首字符 { 或 [ → JSON.parse 成功：
   a. 结果为 Array → jsonarray（元素全为对象 → 表格形式，见 §7.3；否则降级 json 代码块）
   b. 结果为 Object → json（格式化展示）
   c. parse 失败 → 继续向下
3. YAML 启发式：首行 '---' 或 ≥2 行匹配 /^[\w.-]+\s*:/ → yaml
4. 兜底 → text
```

### 7.2 渲染控件

| 识别类型 | 展示控件 | 说明 |
|---|---|---|
| JSON | 只读代码块 + `highlight(content, 'json')` | 先 `JSON.stringify(parsed, null, 2)` 格式化再高亮 |
| **JSON Array** | **el-table 表格（列自动推断）+ 展开行渲染嵌套对象** | 详见 §7.3 |
| YAML | 只读代码块 + `highlight(content, 'yaml')` | **需在 utils.ts LANGS 补 yaml token 定义**（~5 行） |
| TEXT | 等宽字体 `<pre>` 纯文本块 | 不高亮 |

- 区块标题行右侧展示类型徽标：`JSON` / `JSON Array` / `YAML` / `TEXT`（小 tag）
- 代码块复用 CodeEditor 的暗色底 + token 样式（只读，无 textarea 层），带复制按钮
- 识别结果在展示时计算（computed），不存字段——原始字符串是唯一数据源

### 7.3 JSON Array 表格化渲染（Q7）

**列推断（schema inference）**：
- 列 = 全体元素 key 的并集，按首次出现顺序排列
- 列类型按值类型判定：string/number/boolean/null → 普通列（超长省略 + tooltip）；object → 嵌套列
- 异构数组字段缺失显示 `-`

**嵌套对象渲染**：
- 嵌套列单元格显示 `{N 个字段}` 文字提示；含嵌套对象的行自动带 el-table 原生展开箭头
- 展开区：每个嵌套对象渲染为独立区块（嵌套 key 作小标题 + key-value 两列迷你表格）
- 嵌套对象内的值若为数组 → 展开区内渲染为 JSON 代码片段

**嵌套深度边界**：v1 只支持**一层嵌套**（嵌套对象内再出现对象）→ 展开区内该值降级为 JSON 代码块，不再递归展开。

**表格约束**：
- 仅当至少一行存在嵌套对象时才出现展开列
- 列数 > 6 → 表格内部横向滚动（弹窗宽度不变 640px）
- 元素数 > 20 → 表格 max-height 300px 内部纵向滚动
- 空数组 → 空态文案「返回信息为空数组」

### 7.4 已知边界（已评估，可接受）

| 场景 | 处理 |
|---|---|
| 纯文本含冒号（如 `Error: disk full` 单行） | YAML 启发式要求 ≥2 行 key:value 或 `---` 开头，单行不误判 |
| JSON 也是合法 YAML | JSON.parse 优先，不会落到 yaml 分支 |
| 畸形 JSON（parse 失败） | 降级 text，不报错 |
| 数组元素非对象（纯标量或对象/标量混合） | 整体降级 json 代码块，不渲染表格 |
| 深层嵌套（嵌套对象内再有对象） | 展开区内降级 JSON 代码块（v1 只支持一层） |
| 超长返回（>100 行） | 代码块 max-height 300px + 内部滚动 |
