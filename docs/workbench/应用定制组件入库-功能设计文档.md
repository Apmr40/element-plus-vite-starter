## 3.4.1 功能定义

在操作工作台「操作组件 → 应用定制」分区，提供**新增操作**入口，支持用户通过弹窗表单录入自定义操作组件信息，经保存草稿 → 提交审批 → 审批通过后入库，最终出现在「正式操作」列表中。

本功能包含**两种入库模式**：

| 模式 | 说明 | 数据来源 |
|------|------|----------|
| **定制模式** | 从零创建操作组件，手动配置全部参数 | 用户手工录入 |
| **实例固化模式** | 选择公共组件，将其参数固化为特定配置 | 继承公共组件 + 用户填值 |

### 核心流程

```
应用定制 → 点击「新增操作」
  → 选择入库模式（定制 / 实例固化）
  → Step1: 基本信息录入
  → Step2: 参数配置（定制：手动添加 / 实例：继承+固化值）
  → Step3: 确认预览
  → 保存草稿 (confstatus=2)
  → [提交审批 → confstatus=3 → 外部工单 → 审批通过 → confstatus=1]（本期不实现）
  → 入库完成 → 出现在「正式操作」列表
```

## 3.4.4 业务规则

### BR-01 入库模式互斥
- 定制模式和实例固化模式在弹窗内通过 Radio 切换，**切换后清空已填数据**（需二次确认）
- 模式决定 Step2 的交互形态，不可混合

### BR-02 定制模式规则
- `servicename`（操作名称）全局唯一，不可与公共组件/已有定制组件重名
- 参数数量不做强制限制（templateType=0 代理命令可为固定命令，无需参数）
- `datatype`（控件类型）决定前台执行时的渲染方式：
  - 0/NULL → input 输入框
  - 1 → 单选框（datavalue 存选项，逗号分隔）
  - 2 → 多选框（datavalue 存选项，逗号分隔）
  - 3 → 时间下拉框
  - 4 → 计数器
- `parmcheckflag` 校验矩阵：

  | 值 | 必填 | 校验 | 前台行为 |
  |----|------|------|----------|
  | 0 | 否 | 否 | 无约束 |
  | 1 | 否 | 是 | 有值时正则校验 |
  | 2 | 是 | 否 | 仅必填提示 |
  | 3 | 是 | 是 | 必填 + 正则校验 |

- `encryptflag=1` 时，前台执行弹窗中该参数以密码框（`***`）展示

### BR-02a 模板编辑规则（templateType 路由）

| templateType | dictcode | 模板表 | Step2 编辑形态 | 参数替换方式 |
|-------------|----------|--------|---------------|-------------|
| 0 | agentCommand | 无 | 单行命令输入框 | 参数作为命令参数 |
| 1 | shellTemplate | scriptlibrary | 代码编辑器（shell 语法高亮） | `${param_name}` |
| 2 | python2Template | scriptlibrary | 代码编辑器（python 语法高亮） | `${param_name}` |
| 3 | transTemplate | transtemplate | Postman 风格：Method + URL + Headers + Body | `{{param_name}}` |
| 5 | sqlTemplate | scriptlibrary | 代码编辑器（sql 语法高亮） | `${param_name}` |
| 6 | python3Template | scriptlibrary | 代码编辑器（python 语法高亮） | `${param_name}` |
| 7 | PodShellTemplate | scriptlibrary | 代码编辑器（shell 语法高亮）+ Pod 选择器 | `${param_name}` |
| 8 | sqlChange | scriptlibrary | 代码编辑器（sql 语法高亮）+ 变更审批标记 | `${param_name}` |
| - | groovy（待分配） | scriptlibrary | 代码编辑器（groovy 语法高亮），scripttype='a' | `${param_name}` |

> 字典来源：SERV_DICT (DICTTYPE=08)。本期前端仅实现：shell(1) / python2(2) / python3(6) / sql(5) / groovy(待分配,scripttype='a') / API(3)。
> templateType=4(servApi)、9(toolUrl) 待细化，本期下拉中不展示。

**脚本模板编辑（templateType=1/2/5/6/7/8 + groovy）：**
- 模板来源（新建/选择已有）为后端属性，不与前台业务规则关联，前台仅按脚本类/API类/实例类一级分类渲染编辑区
- 新建时：scripttype 由 templateType 自动映射：
  - 1→shell, 2→python2, 5→sql, 6→python3, 7→podshell, 8→sqlchange, groovy→'a'（待分配 templateType）
- 代码编辑器支持语法高亮（shell / python / sql / groovy，demo 阶段 groovy 按 'a' 类型实现）
- templateType=7(PodShell) 额外展示 Pod/容器选择器
- templateType=8(sqlChange) 额外标记变更审批属性
- 脚本内预埋参数变量格式：`${param_name}`，保存时自动扫描提取变量列表
- 提取的变量自动同步到参数配置表格（可编辑中文名、校验规则等）
- 保存时写入 `asmp_th_scriptlibrary`（content + parameterdes）
- **成功判定规则**：选填，默认 `exit_code==0`；用户可自定义（如 `output.contains('SUCCESS')`）

**API报文模板编辑（templateType=3）：**
- 模板来源（新建/选择已有）为后端属性，前台按 API 类渲染 Postman 风格编辑区
- Postman 风格布局：
  - 第一行：Method 下拉（GET/POST/PUT/DELETE/TCP）+ URL 输入框
  - Headers：键值对动态表格
  - Body：代码编辑器（JSON/XML/Text），支持 `{{param_name}}` 埋点
- 保存时写入 `asmp_ao_trans_template`（callmethod + url + header + request）
- 报文内 `{{param_name}}` 埋点自动扫描提取，同步到参数配置表格
- **成功判定规则**：必填，写入 `successflag` 字段（如 `response.code == 200 && response.body.status == 'success'`）

**参数双向同步：**
- 模板内变量 → 自动生成参数行（parmname 取自变量名，datatype 默认 0）
- 参数表格手动添加的行 → 不反向写入模板（仅作为执行时传参）
- 删除模板内变量 → 对应自动生成的参数行标记为"待清理"（不自动删除，用户确认）

### BR-03 实例固化模式规则
- 来源组件仅可选择 `confstatus=1`（已启用）的公共组件，通过 `servicename` 关联
- 选择来源组件后，**自动继承**其全部参数定义（参数名、控件类型、校验规则）
- 实例固化组件执行时**复用来源公共组件的 templateType + templateId**，不创建独立模板
- 用户仅需填写每个参数的**固化值**（`datavalue`）
- 固化值必须符合来源参数的校验规则（`parmcheckflag` + `parmcheckapiid`）
- 固化值填写后，前台执行时**不再显示该参数输入框**，直接使用固化值
- `successrule`（成功判定规则）为必填，支持多行文本
- 实例名称（`instancename`）自动生成规则：`{来源组件名}-{应用系统}-{序号}`，可手动修改

### BR-04 状态流转
```
                    本期实现范围
                 ┌──────────────┐
                 │              ▼
  [新建] → 2(草稿) → 1(启用/入库) → 4(禁用)
                 │         ▲
                 │         │  (本期跳过)
                 │    3(待审批) ← 外部工单回调
                 │         │
                 └─────────┘
                   审批驳回→退回草稿
```
- **本期简化**：保存草稿(2) → 提交入库直接变为启用(1)，跳过审批环节
- 预留 `approver`/`approvalid`/`workordid` 字段，后期对接工单系统
- 已入库(1)的组件不可编辑，需先禁用(4)再修改（或创建新版本）

### BR-05 草稿管理
- 草稿仅创建者可编辑/删除（`creator` 字段匹配当前用户）
- 草稿列表按 `modifytime` 倒序排列
- 删除草稿为物理删除（非软删除）
- **删除草稿时模板记录保留**，仅解除 app_serv_info 与模板的关联（templateId 置空）；模板可被其他组件复用
- 从草稿列表点击「编辑」→ 重新打开入库弹窗，回填已填数据

### BR-06 入库后展示
- 入库成功的组件出现在「应用定制 → 正式操作」Tab
- 正式操作卡片展示：操作名称 + 分类标签 + 来源标记（定制/实例固化）+ 创建时间
- 正式操作 dropdown 菜单：查看详情 / 编辑（跳转草稿）/ 禁用 / 复制
- 实例固化组件额外展示：来源公共组件名称 + 固化参数数量

### BR-07 数据写入映射

**定制模式写入表（按 templateType 分）：**

| 步骤 | 目标表 | 写入内容 |
|------|--------|----------|
| Step1 保存 | `iop_mc_app_serv_info` | 基本信息 + confstatus=2 + creator/createtime |
| Step2 保存（脚本类） | `asmp_th_scriptlibrary` | content(脚本) + parameterdes(变量JSON) + scripttype + version；**templateId 同步回写** app_serv_info |
| Step2 保存（API类） | `asmp_ao_trans_template` | callmethod + url + header + request + params + successflag；**templateId 同步回写** app_serv_info |
| Step2 保存（通用） | `iop_mc_app_parm_info` | 每个参数一行（含模板提取的 + 手动添加的） |
| Step2 保存（通用） | `iop_mc_app_serv_parm_rln` | 组件-参数关联（servicename + parmname + orderindex） |
| 提交入库 | `iop_mc_app_serv_info` | confstatus 2→1, modifier/modifytime |

**实例固化模式写入 2 张表：**

| 步骤 | 目标表 | 写入内容 |
|------|--------|----------|
| Step1 保存 | `iop_mc_serv_ins_info` | 实例信息 + serviceid(来源) + confstatus=2 |
| Step2 保存 | `iop_mc_serv_ins_parm` | 每个固化参数一行（instanceid + parmorder + datavalue） |
| 提交入库 | `iop_mc_serv_ins_info` | confstatus 2→1 |

## 3.4.5 操作步骤

### 定制模式

| 步骤 | 用户操作 | 系统响应 |
|------|----------|----------|
| 1 | 点击「新增操作」 | 弹出入库弹窗，默认选中「定制模式」，Step1 |
| 2 | 填写基本信息（名称/分类/描述/模板类型等） | 实时校验必填项和唯一性 |
| 3 | 点击「下一步」 | 校验通过 → 进入 Step2，根据 templateType 渲染对应编辑区 |
| 4a | 脚本类(1/2/5/6/7/8)：新建脚本或选择已有模板 | 新建→代码编辑器(语法高亮)；选择→加载 content 到编辑器 |
| 4b | API类(3)：新建报文或选择已有模板 | 新建→Postman布局；选择→加载到 Method/URL/Headers/Body |
| 4c | 代理命令(0)：输入执行命令 | 单行输入框 |
| 5 | 编辑模板内容，预埋参数变量 | 实时扫描 `${var}` 或 `{{var}}`，自动同步到参数表格 |
| 6 | 在参数表格中补充中文名、校验规则等 | 模板提取行标记 🔗，手动添加行可自由编辑 |
| 7 | 点击「下一步」 | 校验模板内容非空（脚本/API类）→ Step3 确认预览 |
| 8 | 检查预览信息 | 只读展示：基本信息 + 模板内容(代码块) + 参数列表 |
| 9a | 点击「保存草稿」 | 写入主表+模板表+参数表(confstatus=2)，关闭弹窗 |
| 9b | 点击「提交入库」 | 写入全部(confstatus=1)，templateId回写，关闭弹窗 |

### 实例固化模式

| 步骤 | 用户操作 | 系统响应 |
|------|----------|----------|
| 1 | 点击「新增操作」→ 切换「实例固化模式」 | Step1 变为：来源组件选择 + 实例基本信息 |
| 2 | 选择来源公共组件（下拉/搜索） | 加载该组件的参数列表，自动填充实例名称 |
| 3 | 填写实例名称、成功判定规则 | 校验必填 |
| 4 | 点击「下一步」 | 进入 Step2：参数固化值填写 |
| 5 | 为每个继承参数填写固化值 | 按来源参数的控件类型渲染输入控件 |
| 6 | 点击「下一步」 | 校验固化值合规 → Step3 确认预览 |
| 7a | 点击「保存草稿」 | 写入2张表(confstatus=2) |
| 7b | 点击「提交入库」 | 写入2张表(confstatus=1) |

### 交互细节

- **模式切换**：切换时如已填数据，弹出确认框"切换模式将清空已填内容，是否继续？"
- **Step 导航**：Step 指示器可点击回退（不可前进跳步），「下一步」按钮触发当前 Step 校验
- **参数表格（定制）**：
  - 「添加参数」在表格末尾追加空行
  - 行内编辑，每列按字段类型渲染对应控件
  - 支持拖拽行排序（更新 orderindex）
  - 删除行需确认（已填数据时）
- **参数固化（实例）**：
  - 选择来源组件后，表格自动填充参数行（只读列 + 固化值输入列）
  - 固化值控件类型由来源参数 datatype 决定
  - 单选/多选控件的选项来自来源参数 datavalue
- **底部按钮逻辑**：
  - Step1/Step2：显示 [保存草稿] + [下一步]
  - Step3：显示 [上一步] + [保存草稿] + [提交入库]
  - 「提交入库」为 primary 按钮，「保存草稿」为 default 按钮
