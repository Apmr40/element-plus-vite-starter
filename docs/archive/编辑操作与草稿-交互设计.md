# 编辑操作 & 编辑操作草稿 — 交互设计

> 状态：已实现（CustomDraftsTable / handleDraftCommand / 草稿-版本联动均已落地）
> 版本 v1.0 ｜ 基于「新建操作」三步向导（CustomComponentDialog）复用设计
> 关联：`docs/workbench/应用定制组件入库-功能设计文档.md`、`docs/prototypes/应用定制组件入库-交互原型.html`

---

## 1. 核心设计决策

**正式操作不直接编辑，编辑 = 生成草稿副本（版本化）。**

运维平台的正式操作是"线上在跑"的配置，直接改风险高。因此：

- 点「编辑」正式操作 → **不直接改线上**，而是基于当前版本**生成/打开一个编辑草稿**（`CustomDraft.sourceOperationId = 操作id`）
- 草稿期间，**正式操作照常可执行**（旧配置），互不影响
- 草稿提交 → 审批 → 发布后，**覆盖正式操作**，草稿归档

这与现有数据模型完全吻合：`CustomDraft.sourceOperationId` + `hasEditingDraft()` 徽章机制已预留。

**复用原则**：编辑不新建页面/弹窗，全部复用现有三步向导，仅按场景区分「标题 / 横幅 / 字段锁定 / 按钮文案」。

## 2. 两类草稿（关键概念）

| 草稿类型 | 来源 | sourceOperationId | 编辑时字段锁定 |
|---------|------|-------------------|---------------|
| **新建草稿** | 新增操作向导 → 保存草稿 | 无 | 无锁定（等同新建，全部可改） |
| **编辑草稿** | 正式操作 → 编辑 | 有（指向源操作） | 锁定标识类字段 |

> 区分意义：新建草稿是"未定稿的新东西"，随便改；编辑草稿是"线上版本的待发布修订"，身份不能变。

## 3. 入口设计

| 入口 | 位置 | 行为 |
|------|------|------|
| **编辑** | 正式操作卡片 ⋯ 菜单 | 无草稿→创建编辑草稿并打开向导；有草稿→直接打开该草稿（toast 提示"已有编辑中的草稿"） |
| **查看草稿** | 正式操作卡片 ⋯ 菜单（仅有草稿时显示） | 打开**只读预览**（Step3 形态 + 变更对比），含「继续编辑」「提交入库」快捷按钮 |
| **编辑** | 我的草稿卡片 ⋯ 菜单（status=draft / rejected） | 打开向导，回填草稿快照 |
| **点击草稿卡片** | 我的草稿列表 | 等同「编辑」（草稿默认点开即编辑） |

## 4. 草稿状态流

```
                                   ┌──────────────────────────────────┐
                                   │          审批通过/发布            │
                                   ▼                                  │
  [新建·保存草稿] ──▶  草稿 draft ──提交入库──▶ 已提交 submitted ──────▶ 已发布 published
                        ▲   ▲                     │                     (编辑草稿发布时
                        │   │                     │ 审批驳回             覆盖正式操作)
                        │   └─── 重新编辑 ◀────────▼
                        │        (rejected 可编辑后重提)
                        └────────── 追回 recall ◀──┘ (submitted 撤回回到 draft)

  删除草稿：draft / rejected 状态可删；编辑草稿删除后，正式操作恢复无草稿状态（徽章消失）
```

**各状态可用操作：**

| 状态 | 编辑 | 提交入库 | 发布 | 追回 | 删除 | 查看发布状态 |
|------|:---:|:---:|:---:|:---:|:---:|:---:|
| draft 草稿 | ✅ | ✅ | — | — | ✅ | — |
| submitted 已提交 | 🔒只读 | — | — | ✅ | — | ✅ |
| rejected 已驳回 | ✅(修改重提) | ✅ | — | — | ✅ | — |
| published 已发布 | — | — | — | — | — | ✅ |

> ⚠️ 现有代码「编辑」仅在 `status==='draft'` 显示，**建议补上 `rejected`**（驳回后必须能改了重提，否则流程断头）。

## 7. 变更对比（编辑类草稿 Step3 增强）

编辑草稿的「确认预览」步骤，与线上正式版本逐字段 diff：

- 有变更的字段行：左侧加 **琥珀色竖条** + 行尾 `已修改` 小标签
- 预览顶部汇总：**"本次共 N 处变更"**（点击可只高亮变更项）
- 脚本/API 内容变更：展示前后对照（或标注"模板内容有修改"）
- 目的：提交人自查 + 审批人一眼看清改了什么（运维安全刚需）

## 8. 边界与异常

| 场景 | 处理 |
|------|------|
| 编辑正式操作，但已存在草稿 | 不重复创建，直接打开已有草稿，toast"该操作已有编辑中的草稿，已为您打开" |
| 一个操作能否有多个草稿 | 否。`hasEditingDraft` 保证一对一 |
| 编辑草稿发布成功 | 覆盖正式操作配置；草稿 → published；操作「正在编辑」徽章消失 |
| 删除编辑草稿 | 正式操作恢复原状，徽章消失 |
| 草稿 submitted 期间想改 | 先「追回」回 draft，再编辑 |
| 正式操作在草稿期间被执行 | 正常执行**旧配置**；草稿发布后新执行才用新配置 |
| 切换入库模式（仅新建类允许） | 弹确认"切换将清空已填内容"，确认后重置 |
| 编辑时源操作被他人删除 | 打开草稿时校验 sourceOperationId 有效性，失效则提示"源操作已删除，此草稿仅可删除" |

## 10. 版本历史与对比

### 10.1 核心原则

**版本绑定"发布"事件，不绑定草稿。** 草稿/驳回不消耗版本号，只有发布成功才 +1。每个版本存完整快照，支持任意两版对比。

### 10.2 版本模型

```ts
interface OperationVersion {
  versionNo: number                // 1,2,3 → 展示 V1/V2/V3
  publishTime: string
  publisher: string                // 发布人
  changeType: 'create' | 'update'  // V1 = 初始发布
  changeCount: number              // 变更字段数
  changeSummary: string[]          // ["修改脚本内容", "超时 30s→60s"]
  snapshot: CustomComponentForm    // 完整快照，对比的数据源
}
```

DB 映射：新增 `iop_mc_app_serv_version`（serv_id, version_no, snapshot_json, publisher, publish_time, change_summary）。

### 10.3 版本号规则

- V1 = 初始发布；编辑草稿每次发布成功 → 当前版本 +1
- 草稿、驳回、追回均不消耗版本号
- 版本号单调递增，不跳号

### 10.4 三个入口

| 入口 | 位置 | 说明 |
|------|------|------|
| 编辑弹窗横幅 | 版本徽章 + 「历史版本」按钮 | 主入口，编辑时随时看 |
| 操作卡片 ⋯ 菜单 | 「版本历史」 | 不进编辑也能看 |
| Step3 预览 | 对比基线下拉 | 编辑草稿时可切换对比任意历史版本 |

### 10.5 版本历史抽屉（el-drawer，520px，右侧滑出）

- 头部：操作名称 + 当前版本徽章
- 时间线倒序（最新在上），每个节点：版本号 + 状态标签、发布时间、发布人、变更摘要（前 3 条）、快捷按钮
- 当前版本：主色实心节点 + 「当前版本」标签，无对比按钮
- 历史版本：空心节点 + 「与上一版对比」「与当前对比」
- V1 标注「初始版本」

### 10.6 版本对比弹窗（900px，覆盖在抽屉之上）

- 头部：「版本对比 · V2 → V3」+ 双方发布人/时间
- 汇总行：「共 N 处变更」+ 「只看变更项 / 显示全部」切换
- 字段级 diff 表格：字段 | V2 值 | V3 值，变更行琥珀高亮 + 左侧竖条
- 脚本/API 内容字段：行内折叠，点「展开」→ 左右双栏代码对照（行级高亮）
- 未变更字段默认折叠在「显示全部」里，避免噪音

### 10.7 基线冲突检测（关键安全机制）

草稿记录 `baseVersionNo`（创建时基于的版本）。提交入库时：

- 若 线上当前版本 > baseVersionNo → 说明编辑期间有人发布了新版
- 弹二次确认：「线上已更新至 V4（你的草稿基于 V3），继续发布将覆盖 V4 的变更」
- 提供 「查看 V3 → V4 变更」按钮，看完再决定
- 确认发布 → 新版本号 = 当前最大版本 + 1

### 10.8 边界情况

| 场景 | 处理 |
|------|------|
| 只有 V1 | 抽屉仅一个节点，对比按钮禁用 |
| 脚本超长 | diff 折叠，按需展开 |
| 发布人是自己 | 照常显示姓名，不做特殊处理 |
| 编辑中查看历史 | 横幅显示「V3 · 编辑中」，历史抽屉照常打开（不含未发布草稿） |
| 历史版本能否回滚 | v1 不做一键回滚，引导用户「基于某版复制新建」或手动对照修改 |
