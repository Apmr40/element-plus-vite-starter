## 1. 核心设计决策

**一句话：筛选是三个 tab 共享的统一机制（同一 FilterBar 组件 + 同一套 composable 状态），但维度可用性按 tab 裁剪；"权限提示"与"自定义标签"是两个不同概念，本次彻底拆分。**

成立依据（现有代码事实）：

- `favoriteFilter`（收藏 tab 一级分类筛选）已存在 → 收藏区筛选交互有先例，本次是**加维度**不是从零建
- `customFilter`（应用定制 computed 中已接入，无 UI 赋值）→ 筛选机制已预留，缺交互定义
- 应用定制 tab 已有"筛选"按钮（`handleFilterCustom` toast 占位）和"快速修改标签"按钮（占位）→ 入口位置已预留
- `OperationCategory`（6 项枚举）+ `RISK_MAP` 已定义于入库流程 → 操作分类枚举直接复用，不新造

## 2. 概念定义（本次设计的基石）

操作组件上存在**三类不同的"分类/标签"概念**，必须先分清：

| 概念 | 字段 | 取值来源 | 可变性 | 参与筛选 | 视觉 |
|------|------|----------|--------|----------|------|
| 操作分类 | `operationCategory`（新增） | 固定枚举 6 项：查询/验证/启停/配置变更/部署发布/清理回收 | 入库时确定，编辑可改（走既有编辑弹窗） | ✅ 三个 tab 均可 | —（本身不是 tag） |
| 权限提示 | `tags`（现有字段，语义重定义） | 由风险等级推导，允许人工覆盖 | 平台/管理员维护，**用户不可自定义** | ❌ 仅展示 | **实色 tag**（现有 getTagType 配色） |
| 自定义标签 | `customTags`（新增） | 用户在应用系统范围内自由定义 | 用户可增删改（§5） | ✅ 仅应用定制 tab + 收藏 tab | **描边 tag**（effect="plain"） |

### 2.1 权限提示推导链

```
操作分类 ──RISK_MAP──▶ 风险等级 ──推导规则──▶ 权限提示(tags)
 查询        低          [生产办公, 一二线]
 验证/清理回收  中          [仅生产]
 启停/配置变更/部署发布 高  [仅生产, 应急]
```

- 推导是**主要依据，允许人工覆盖**（mock 保留 1 条覆盖样例，见 §3.2）
- 这解释了现有 mock 中 riskLevel↔tags 的强相关但非确定性：大方向是推导，个别是人工覆盖
- 编排分区的"仅生产/应急/运维请求/隔离"是硬编码，不走此链路，不在本次范围

### 2.2 为什么权限提示不能当筛选维度

权限提示是**执行约束的展示**（告诉你这个操作能在什么环境跑），不是用户组织操作的维度。用它筛选会产生"仅生产 ∩ 应急"这类无业务意义的组合。筛选维度只保留：一级分类（收藏已有）、操作分类、自定义标签。

## 3. 数据模型变更

### 3.1 类型（src/demo/types/workbench.ts）

```ts
export interface OperationComponent {
  // ... 现有字段不动
  operationCategory?: OperationCategory  // 操作分类（公共组件 + 定制均有）
  customTags?: string[]                  // 自定义标签（应用系统范围内公用；公共组件恒为空）
  // tags 字段保留，语义重定义为"权限提示"，注释更新
}
```

### 3.2 mock 补齐规则

**操作分类按操作名语义推导**（公共组件 ~70 条全量补齐）：

| 名称关键词 | 操作分类 | 风险 |
|-----------|---------|------|
| 查看/查询/检查/状态/巡检 | 查询 | 低 |
| 健康检查/连通性 | 验证 | 中 |
| 重启/启停/切换/回滚/重跑 | 启停 | 高 |
| 配置更新/同步/调整/重载/变更 | 配置变更 | 高 |
| 部署/发布/迁移 | 部署发布 | 高 |
| 清理/备份/归档/回收 | 清理回收 | 中 |

**riskLevel 以 operationCategory 为准经 RISK_MAP 反算**，现有 4 条偏离数据同步修正：

| 操作 | 原值 | 修正 |
|------|------|------|
| op0102-1 Windows服务管理 | medium+[生产办公,一二线] | 启停 → high → [仅生产,应急] |
| op0402-2 Nginx重载配置 | medium+[仅生产,应急] | 配置变更 → high（权限提示不变） |
| op0602-2 Deployment副本数调整 | medium+[仅生产,应急] | 配置变更 → high（权限提示不变） |
| op9901-3 演练结果收集 | low+[仅生产] | 查询 → low，**保留 [仅生产] 作为人工覆盖样例** |

**实现补充（v1.1）**：op0901-1 定制应用健康检查的 V3 版本快照为「查询/低」，关键词规则会推导为验证/中；快照是发布态事实（编辑弹窗从快照预填），故 op0901-1 的分类以快照为准（查询），列表与编辑保持一致。

**自定义标签**：仅应用定制 3 条补示例值（如 `['核心链路']`、`['月度巡检']`），公共组件不补。

## 4. 筛选入口与 UI（按 tab）

### 4.1 统一 FilterBar 形态

筛选条置于列表上方，与收藏区现有 `.favorite-filter` 同风格（`筛选：` 前缀 + 行内控件）：

```
筛选： 操作分类 [全部|查询|验证|启停|配置变更|部署发布|清理回收]   自定义标签 [▾ 多选下拉]   清除
```

- **操作分类**：tag 样式单选（含"全部"），与收藏区现有一级分类筛选交互一致；**全量 6 项恒定**（Q2）
- **自定义标签**：`el-select` 多选，选项 = 当前应用系统范围内的标签聚合；支持 `allow-create` 行内新建（新建即入库，与应用定制内新建等价）
- **清除**：任一筛选激活时出现，一键清空本 tab 全部筛选条件
- 搜索框与筛选条并存，关系为 AND（Q5）

### 4.2 三个 tab 的维度裁剪

| Tab | 一级分类 | 操作分类 | 自定义标签 | 说明 |
|-----|---------|---------|-----------|------|
| 公共组件 | —（已有 tab 导航承担） | ✅ | ❌ | 公共组件无自定义标签；筛选条仅出现在二级目录点入后的操作列表视图，目录视图不显示 |
| 我的收藏 | ✅（现有 tag 筛选，保留不动） | ✅ | ✅ | 现有 `.favorite-filter` 为第一行，新 FilterBar 为第二行 |
| 应用定制 | — | ✅ | ✅ | 现有"筛选"按钮移除，替换为列表上方 FilterBar；**仅正式操作 tab 显示**，草稿 tab 不显示（草稿实体无这两个字段） |

### 4.3 收藏区的特殊性（Q4/Q6）

- 收藏是全局的（跨应用系统、混合公共+定制）
- 自定义标签下拉选项 = **当前选中应用系统**的标签聚合；选中某标签后，其他系统的定制项与全部公共组件（无 customTags）自然落选
- 空态文案：`当前筛选条件下暂无匹配的收藏操作（标签筛选仅作用于当前应用系统的定制操作）`
- 收藏区标签**只读展示**（Q6），修改回到应用定制 tab

## 5. 自定义标签管理（应用定制 tab）

### 5.1 单个操作：编辑标签

- 入口：操作卡片更多菜单新增「编辑标签」（置于 删除/复制 之前）；表格视图操作列下拉同步
- 交互：`el-popover`，内容 = 当前应用系统全部标签的 checkbox 列表（已选中的勾选）+ 底部「+ 新标签」行内输入
- 确认 → 整体覆盖该操作的 `customTags`
- 权限提示**不出现**在此面板（不可编辑，概念隔离）

### 5.2 批量：快速修改标签（现有按钮落地）

1. 点击「快速修改标签」→ 进入批量模式：正式操作卡片/表格行出现勾选框（复用草稿勾选样式）
2. 底部出现批量栏：`已选择 N 项` + 标签多选下拉（allow-create）+「应用」+「取消」
3. 应用 → **增量合并**：所选标签并入所选操作的 customTags（不删除已有标签）；toast `已为 N 个操作添加标签`
4. 需要删标签时走 5.1 单个编辑（批量只加不减，避免误删）
5. 应用/取消后退出批量模式

### 5.3 标签生命周期（v1 简化）

- **无独立标签库实体**：标签 = 全体操作 customTags 的引用聚合，新建走 5.1/5.2 的行内创建
- 标签删除/重命名（全局影响）→ v2，见非目标

## 7. 筛选行为规则

1. 维度间 AND，筛选与搜索 AND（Q5）
2. 操作分类枚举全量恒定，选中无匹配项的分类 → 列表空态 `无匹配数据，试试清除筛选`
3. 筛选状态存于 composable（ref），**不持久化**；切换 tab（handleSourceChange）时清空——与现有重置逻辑一致
4. 切换应用系统时：已选自定义标签若不存在于新系统 → 该条件自动清除
5. 卡片 ⇄ 表格双视图共享同一 filtered computed，筛选结果跨视图一致；表格勾选与筛选共存（筛选后被过滤行的勾选自动失效，同现有草稿逻辑）

## 8. 边界与异常

| 场景 | 处理 |
|------|------|
| 新标签为空/纯空格 | 创建按钮禁用，输入框红色提示 |
| 新标签与现有标签重复 | 创建时去重等价（选中已有标签），不重复创建 |
| 标签名超长 | ≤12 字符，超出截断输入并提示 |
| 单操作标签数量 | ≤5 个，超出时 checkbox 禁用 + tooltip 提示 |
| 切换应用系统后已选标签失效 | 自动清除该筛选条件，不打断其他条件 |
| 收藏区标签筛选落空 | 专属空态文案（§4.3） |
| 应用定制草稿 tab | 不显示 FilterBar（草稿无 operationCategory/customTags 字段） |
| 公共组件目录视图 | 不显示 FilterBar（点入二级分类后才出现） |
| 批量模式中筛选变化 | 筛选变化时清空批量勾选（可见行已变） |
| 编辑标签 popover 打开时该操作被删除 | 关闭 popover + toast 提示（demo 阶段可简化为直接关闭） |
